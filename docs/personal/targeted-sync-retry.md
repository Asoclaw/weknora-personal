# 失败项定向重试

摹客数据源卡片和同步历史的失败提示中提供“重试失败项”。卡片针对当前错误对应的记录，历史入口针对展开的那条记录。当前同步继续运行；同一来源已有任务时按钮禁用。

项目读取失败只检查该项目，画板失败只检查该画板。图片优先、文字兜底和内容比较沿用现有流程；内容未变时保留文件 ID、原文件、片段和 Wiki。重试不扫描删除，也不会自动恢复已取消或已失败的解析任务。解析任务恢复继续使用其原有入口。

每次重试新建同步日志，以 `retry_of_log_id` 关联原记录。原失败历史不改写；重试旧记录不会清除更新的同步结果。

## API 与兼容

- `POST /api/v1/datasource/{id}/logs/{log_id}/retry`：Admin 权限，成功返回 `202` 和新的同步日志；同来源已有同步时返回 `409`。
- 同步结果 JSON 中的 `retry_targets` 保存完整失败目标及阶段，独立于最多 100 条的错误展示样本；`retry_scope` 防止连接或团队更换后误用旧目标。无需数据库表结构迁移。
- 旧日志优先通过已保存来源标识定位，再核对完整路径及当前项目树。同名歧义、目标缺失或超出范围会明确保留原因，不扩大为全范围同步。旧日志未保存的失败目标无法凭空恢复，缺失数量记入 `unresolved_failures`。
- 手动、定时和定向重试统一在事务中检查入队冲突，并通过 Redis 执行租约串行处理同一来源。

## 验证

后端覆盖单画板、项目、旧日志、改名后的稳定标识、同名歧义、范围隔离、超过 100 项失败、游标保留、禁用删除、取消任务保护、权限、入队冲突及执行租约。保留现有内容稳定性和持久化片段、Wiki 回归。

隔离接口样本中，一次失败包含一个项目和一个画板。重试不访问无关项目及已成功的其他画板，4 份文件和 16 个片段的 ID 保持一致，原失败日志不变，重复提交返回 `409`。使用独立测试账号、数据库、Redis DB 和文件卷，不使用正式摹客凭证。

前端完成类型检查、多语言检查、生产构建和共用按钮交互测试；在固定本地地址的新建无头浏览器中验证两个实际入口、执行期间禁用及结果刷新，不复用用户浏览器会话。

完整 Linux 构建保留 `anydoc`。`grpc-gateway` v1 仍引用现代 `genproto` 已移除的 FieldMask 路径，使用本地类型别名兼容包指向官方 `fieldmaskpb.FieldMask`，不改变 Protobuf 类型或序列化。
